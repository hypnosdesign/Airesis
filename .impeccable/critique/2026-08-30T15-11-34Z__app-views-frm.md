## Design Specificity Verdict

Group name, public/private visibility, authorship, replies, views, and recent activity make the domain recognizable as a civic forum. The presentation itself remains generic Forem scaffolding: wide legacy tables, weak state language, and controls that disappear behind runtime failures. The deterministic detector is intentionally deferred to the final G09 gate.

## What's Working

- The forum show route identifies the group, visibility, author, reply count, view count, and recent activity.
- The primary new-topic action is clear and the Trix toolbar exposes accessible names with 44 px controls.
- The existing shell and global announcement remain visually coherent.
- Linux ARM64 Chromium and ChromeDriver 151 run Selenium successfully; current failures are application and test-contract failures, not driver availability.

## Priority Issues

1. **P0 — Arbitrary cross-forum moderation.** `Frm::Post.moderate!` resolves global post IDs and dispatches unsanitized input with `send`, allowing a moderator of one forum to approve, spam, or invoke destructive methods on another forum's post. Topic moderation repeats the unsafe dispatch pattern.
2. **P0 — Cross-group moderator membership mutation.** `Frm::Admin::MembersController` authorizes the URL group but resolves `mod_id` globally, so one group's administrator can mutate another group's moderator group.
3. **P1 — Published routes exceed implemented actions.** There are 83 Frm routes, 43 GET routes, and 33 entries pointing to missing actions/controllers. Constrain resources to supported behavior or implement the retained actions; final coverage must report zero missing Frm action pairs.
4. **P1 — Core rendering contracts are broken.** The admin category partial has malformed ERB; topic moderation passes the wrong helper arguments and parameter namespace; mass moderation uses POST against PUT-only routes; duplicated `data` hashes turn PUT toggles into GET.
5. **P1 — Primary paths fail at runtime.** Forum index, category, topic show, and moderation return the global error page, blocking reading and governance.
6. **P1 — Subscribe/unsubscribe mutate state through GET.** These endpoints are unsafe under prefetch and crawler behavior and need explicit non-GET verbs.
7. **P1 — Tests accept server errors.** Request specs whitelist 500 and system specs still drive removed CKEditor helpers, obscuring regressions.
8. **P2 — Response semantics are inconsistent.** Invalid forms often return 200 rather than 422 and successful mutations redirect with 302 rather than 303.
9. **P2 — Responsive and semantic structure is weak.** Topic tables overflow at 390 px, pages lack a primary H1, post columns are rigid, breadcrumb targets are small, and several actions use `btn-xs`.
10. **P2 — Moderation state is internally contradictory.** New posts are immediately approved by a callback, making the pending queue ineffective.

## Acceptance Criteria

- Scope moderation to the current forum, allow only `approve` and `spam`, reject unknown operations, and cover cross-forum and destructive payloads.
- Resolve moderator groups through `@group.mods`, reject missing users, and cover cross-group attempts.
- Reach zero Frm routes without a concrete controller action.
- Compile every Frm ERB template and make all retained Turbo/verb/parameter contracts valid.
- Return 422 for invalid submissions and 303 after state-changing HTML requests.
- Replace permissive request assertions and CKEditor-era system helpers with exact contracts and Trix-compatible interactions.
- Provide one H1/main hierarchy, responsive topic/post composition, clear empty/pending/locked state, contextual recovery, and 44 px interactive targets.
